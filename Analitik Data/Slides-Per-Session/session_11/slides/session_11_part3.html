Confusion Matrix

Definisi

Confusion Matrix adalah tabel yang menampilkan performa model klasifikasi dengan membandingkan prediksi dengan nilai aktual.

Struktur Confusion Matrix (Binary Classification):

Predicted: Negative (0)
Predicted: Positive (1)
Actual: Negative (0)
True Negative (TN)
Correct!
False Positive (FP)
Type I Error
Actual: Positive (1)
False Negative (FN)
Type II Error
True Positive (TP)
Correct!

Contoh: Medical Test

  • TP: Pasien sakit, diprediksi sakit ✓
  • TN: Pasien sehat, diprediksi sehat ✓
  • FP: Pasien sehat, diprediksi sakit ✗ (False Alarm)
  • FN: Pasien sakit, diprediksi sehat ✗ (Missed Detection)

Metrik Evaluasi Klasifikasi

1. Accuracy (Akurasi)

\[ Accuracy = \frac{TP + TN}{TP + TN + FP + FN} \]

Interpretasi: Proporsi prediksi yang benar dari keseluruhan prediksi

  • Kapan digunakan: Dataset balanced
  • Kelemahan: Misleading pada imbalanced data

2. Precision (Presisi)

\[ Precision = \frac{TP}{TP + FP} \]

Interpretasi: Dari semua yang diprediksi positif, berapa yang benar-benar positif?

  • Kapan digunakan: Cost of False Positive tinggi
  • Contoh: Spam detection (jangan blokir email penting)

Recall dan F1-Score

3. Recall / Sensitivity / True Positive Rate (TPR)

\[ Recall = \frac{TP}{TP + FN} \]

Interpretasi: Dari semua yang sebenarnya positif, berapa yang berhasil terdeteksi?

  • Kapan digunakan: Cost of False Negative tinggi
  • Contoh: Cancer detection (jangan miss pasien sakit)

4. F1-Score (Harmonic Mean of Precision & Recall)

\[ F1 = 2 \times \frac{Precision \times Recall}{Precision + Recall} \]

Interpretasi: Balance antara Precision dan Recall

  • Kapan digunakan: Butuh balance, imbalanced data
  • Range: 0 - 1 (semakin tinggi semakin baik)

Trade-off: Precision vs Recall

Precision vs Recall Trade-off

Meningkatkan satu metrik sering menurunkan metrik lainnya

Skenario Prioritas Metrik Utama Alasan
Medical Diagnosis Jangan miss pasien sakit Recall ↑ False Negative berbahaya (pasien sakit tidak terdeteksi)
Spam Detection Jangan blokir email penting Precision ↑ False Positive mengganggu (email penting di spam)
Fraud Detection Deteksi semua fraud Recall ↑ Miss fraud = kerugian finansial besar
Recommendation System Rekomendasi harus akurat Precision ↑ Rekomendasi buruk = user experience jelek
Balanced Case Balance keduanya F1-Score ↑ Tidak ada prioritas jelas

Implementasi: Confusion Matrix & Metrics

from sklearn.metrics import (confusion_matrix, accuracy_score, 
                             precision_score, recall_score, f1_score,
                             classification_report)
import matplotlib.pyplot as plt
import seaborn as sns

# Assuming we have y_test and y_pred from previous model

# 1. Confusion Matrix
cm = confusion_matrix(y_test, y_pred)
print("Confusion Matrix:")
print(cm)

# Visualize Confusion Matrix
plt.figure(figsize=(8, 6))
sns.heatmap(cm, annot=True, fmt='d', cmap='Blues', 
            xticklabels=['Negative', 'Positive'],
            yticklabels=['Negative', 'Positive'])
plt.ylabel('Actual')
plt.xlabel('Predicted')
plt.title('Confusion Matrix')
plt.show()

# 2. Calculate Metrics
accuracy = accuracy_score(y_test, y_pred)
precision = precision_score(y_test, y_pred)
recall = recall_score(y_test, y_pred)
f1 = f1_score(y_test, y_pred)

print(f"\nAccuracy:  {accuracy:.4f}")
print(f"Precision: {precision:.4f}")
print(f"Recall:    {recall:.4f}")
print(f"F1-Score:  {f1:.4f}")

# 3. Classification Report (all metrics at once)
print("\n=== Classification Report ===")
print(classification_report(y_test, y_pred))

ROC Curve dan AUC

ROC (Receiver Operating Characteristic) Curve

Grafik yang menampilkan trade-off antara True Positive Rate (TPR) dan False Positive Rate (FPR) pada berbagai threshold.

Komponen ROC:

\[ TPR = Recall = \frac{TP}{TP + FN} \]

\[ FPR = \frac{FP}{FP + TN} \]

ROC Curve: Plot TPR (y-axis) vs FPR (x-axis)

AUC (Area Under the Curve)

  • AUC = 1.0: Perfect classifier
  • AUC = 0.9 - 1.0: Excellent
  • AUC = 0.8 - 0.9: Good
  • AUC = 0.7 - 0.8: Fair
  • AUC = 0.5: Random guessing (no better than coin flip)
  • AUC < 0.5: Worse than random (model predicts opposite!)

Implementasi: ROC Curve & AUC

from sklearn.metrics import roc_curve, roc_auc_score, auc
import matplotlib.pyplot as plt

# Get probability predictions (not just class labels)
y_pred_proba = model.predict_proba(X_test)[:, 1]  # Probability of class 1

# Calculate ROC curve
fpr, tpr, thresholds = roc_curve(y_test, y_pred_proba)

# Calculate AUC
roc_auc = roc_auc_score(y_test, y_pred_proba)
# Alternative: auc_score = auc(fpr, tpr)

print(f"AUC Score: {roc_auc:.4f}")

# Plot ROC Curve
plt.figure(figsize=(10, 8))
plt.plot(fpr, tpr, color='darkorange', lw=2, 
         label=f'ROC curve (AUC = {roc_auc:.2f})')
plt.plot([0, 1], [0, 1], color='navy', lw=2, linestyle='--',
         label='Random Classifier (AUC = 0.50)')
plt.xlim([0.0, 1.0])
plt.ylim([0.0, 1.05])
plt.xlabel('False Positive Rate')
plt.ylabel('True Positive Rate')
plt.title('Receiver Operating Characteristic (ROC) Curve')
plt.legend(loc="lower right")
plt.grid(True, alpha=0.3)
plt.show()

# Find optimal threshold
optimal_idx = np.argmax(tpr - fpr)
optimal_threshold = thresholds[optimal_idx]
print(f"Optimal Threshold: {optimal_threshold:.4f}")

Precision-Recall Curve

Kapan menggunakan PR Curve vs ROC Curve?

  • ROC Curve: Baik untuk balanced dataset
  • Precision-Recall Curve: Lebih baik untuk imbalanced dataset

Contoh Imbalanced Data:

Fraud Detection: 99% legitimate, 1% fraud

  • ROC Curve bisa misleading (AUC tinggi meski model buruk)
  • PR Curve lebih informatif untuk kasus minority class
from sklearn.metrics import precision_recall_curve, average_precision_score

# Calculate Precision-Recall curve
precision, recall, thresholds = precision_recall_curve(y_test, y_pred_proba)

# Calculate Average Precision (AP)
ap_score = average_precision_score(y_test, y_pred_proba)

print(f"Average Precision Score: {ap_score:.4f}")

# Plot PR Curve
plt.figure(figsize=(10, 8))
plt.plot(recall, precision, color='blue', lw=2,
         label=f'PR curve (AP = {ap_score:.2f})')
plt.xlabel('Recall')
plt.ylabel('Precision')
plt.title('Precision-Recall Curve')
plt.legend(loc="lower left")
plt.grid(True, alpha=0.3)
plt.show()

Cross-Validation

Apa itu Cross-Validation?

Teknik untuk mengevaluasi model dengan membagi data menjadi multiple folds, melatih dan menguji model pada kombinasi berbeda.

K-Fold Cross-Validation:

  1. Bagi data menjadi K bagian (folds)
  2. Untuk setiap fold:
    • Gunakan 1 fold sebagai test set
    • Gunakan K-1 fold lainnya sebagai training set
    • Train model dan evaluasi
  3. Rata-rata hasil dari K iterasi

Keuntungan Cross-Validation:

  • Semua data digunakan untuk training dan testing
  • Evaluasi lebih reliable (mengurangi variance)
  • Mendeteksi overfitting
  • Lebih baik untuk dataset kecil

Kekurangan:

  • Lebih lambat (train model K kali)
  • Tidak cocok untuk time-series data (gunakan TimeSeriesSplit)

Implementasi: Cross-Validation

from sklearn.model_selection import cross_val_score, cross_validate
from sklearn.ensemble import RandomForestClassifier
import numpy as np

# Create model
model = RandomForestClassifier(n_estimators=100, random_state=42)

# Method 1: Simple cross-validation with single metric
cv_scores = cross_val_score(model, X, y, cv=5, scoring='accuracy')

print("Cross-Validation Scores:", cv_scores)
print(f"Mean Accuracy: {cv_scores.mean():.4f} (+/- {cv_scores.std():.4f})")

# Method 2: Cross-validation with multiple metrics
scoring = ['accuracy', 'precision', 'recall', 'f1', 'roc_auc']
cv_results = cross_validate(model, X, y, cv=5, scoring=scoring)

print("\n=== Cross-Validation Results (5-Fold) ===")
for metric in scoring:
    scores = cv_results[f'test_{metric}']
    print(f"{metric.capitalize():12s}: {scores.mean():.4f} (+/- {scores.std():.4f})")

# Method 3: Stratified K-Fold (maintains class distribution)
from sklearn.model_selection import StratifiedKFold

skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
cv_scores_strat = cross_val_score(model, X, y, cv=skf, scoring='f1')

print(f"\nStratified CV F1-Score: {cv_scores_strat.mean():.4f}")

Evaluasi Multiclass Classification

Averaging Methods untuk Multiclass:

Ketika ada > 2 kelas, metrik seperti precision/recall perlu di-aggregate

Method Deskripsi Kapan Digunakan
macro Hitung metrik per kelas, lalu rata-rata (semua kelas equal weight) Semua kelas sama penting
weighted Rata-rata berbobot berdasarkan jumlah sampel per kelas Imbalanced data, kelas besar lebih penting
micro Aggregate kontribusi semua kelas untuk hitung metrik Dataset sangat imbalanced
samples Hitung metrik untuk setiap instance Multilabel classification 
from sklearn.metrics import precision_recall_fscore_support

# Calculate metrics for multiclass
precision_macro = precision_score(y_test, y_pred, average='macro')
recall_macro = recall_score(y_test, y_pred, average='macro')
f1_macro = f1_score(y_test, y_pred, average='macro')

print("Macro-averaged Metrics:")
print(f"  Precision: {precision_macro:.4f}")
print(f"  Recall:    {recall_macro:.4f}")
print(f"  F1-Score:  {f1_macro:.4f}")

# Per-class metrics
precision, recall, f1, support = precision_recall_fscore_support(y_test, y_pred)

print("\nPer-Class Metrics:")
for i in range(len(precision)):
    print(f"Class {i}: P={precision[i]:.3f}, R={recall[i]:.3f}, F1={f1[i]:.3f}")

Panduan Memilih Metrik Evaluasi

Kondisi Metrik yang Direkomendasikan Alasan
Balanced Dataset Accuracy, F1-Score Semua kelas terwakili dengan baik
Imbalanced Dataset F1-Score, Precision-Recall AUC Accuracy bisa misleading
Cost of FP tinggi Precision Fokus mengurangi false positive
Cost of FN tinggi Recall Fokus mengurangi false negative
Need probabilistic output ROC-AUC, Log Loss Evaluasi confidence prediksi
Multiclass balanced Macro F1-Score Treat semua kelas equally
Multiclass imbalanced Weighted F1-Score Consider class distribution
Ranking/Ordering important ROC-AUC, NDCG Measure ranking quality

Complete Model Evaluation Pipeline

import numpy as np
import pandas as pd
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.ensemble import RandomForestClassifier
from sklearn.metrics import *

def evaluate_model(model, X_train, X_test, y_train, y_test):
    """Comprehensive model evaluation"""
    
    # Train model
    model.fit(X_train, y_train)
    
    # Predictions
    y_pred = model.predict(X_test)
    y_pred_proba = model.predict_proba(X_test)[:, 1]
    
    print("="*60)
    print("MODEL EVALUATION REPORT")
    print("="*60)
    
    # 1. Basic Metrics
    print("\n1. BASIC METRICS")
    print(f"   Accuracy:  {accuracy_score(y_test, y_pred):.4f}")
    print(f"   Precision: {precision_score(y_test, y_pred):.4f}")
    print(f"   Recall:    {recall_score(y_test, y_pred):.4f}")
    print(f"   F1-Score:  {f1_score(y_test, y_pred):.4f}")
    print(f"   ROC-AUC:   {roc_auc_score(y_test, y_pred_proba):.4f}")
    
    # 2. Confusion Matrix
    print("\n2. CONFUSION MATRIX")
    print(confusion_matrix(y_test, y_pred))
    
    # 3. Classification Report
    print("\n3. CLASSIFICATION REPORT")
    print(classification_report(y_test, y_pred))
    
    # 4. Cross-Validation
    cv_scores = cross_val_score(model, X_train, y_train, cv=5, 
                                scoring='f1')
    print(f"\n4. CROSS-VALIDATION (5-Fold)")
    print(f"   F1 Scores: {cv_scores}")
    print(f"   Mean F1:   {cv_scores.mean():.4f} (+/- {cv_scores.std():.4f})")
    
    print("="*60)

# Usage
rf_model = RandomForestClassifier(n_estimators=100, random_state=42)
evaluate_model(rf_model, X_train, X_test, y_train, y_test)

Common Pitfalls dalam Evaluasi Model

❌ Kesalahan yang Sering Terjadi:

  1. Data Leakage: Informasi test set bocor ke training
    • Solusi: Strict train-test split, gunakan pipelines
  2. Hanya lihat Accuracy: Terutama pada imbalanced data
    • Solusi: Lihat multiple metrics (Precision, Recall, F1)
  3. Overfitting to validation set: Tune berulang kali pada val set yang sama
    • Solusi: Gunakan cross-validation, hold-out test set terpisah
  4. Tidak mempertimbangkan business context: Metrik tidak align dengan tujuan bisnis
    • Solusi: Pahami cost of errors, pilih metrik sesuai domain
  5. Ignore class distribution: Model bias ke majority class
    • Solusi: Stratified sampling, class weights, SMOTE

Ringkasan: Evaluasi Model

Poin-poin Penting:

  • Confusion Matrix adalah dasar untuk semua metrik klasifikasi
  • Accuracy baik untuk balanced data, misleading untuk imbalanced
  • Precision: Fokus pada mengurangi False Positive
  • Recall: Fokus pada mengurangi False Negative
  • F1-Score: Balance antara Precision dan Recall
  • ROC-AUC: Evaluasi overall performance across thresholds
  • Cross-Validation: Evaluasi lebih robust, deteksi overfitting

Best Practices:

  • Gunakan multiple metrics untuk evaluasi komprehensif
  • Pilih metrik sesuai business objective dan class distribution
  • Gunakan cross-validation untuk dataset kecil/medium
  • Visualisasi hasil: Confusion Matrix, ROC Curve, PR Curve
  • Pertimbangkan cost of errors dalam domain problem
  • Monitor model performance di production (tidak hanya development)
